# 发票私密交付与收件确认

本轮将已支付订单的开票申请接到实际 PDF 交付。后台展示订单号、抬头、企业税号和邮箱，管理员上传已开具 PDF 后，Web 与 APP 用户可以下载并明确确认收到；后台显示首次收件时间。

## 行为与权限

- 上传限制 5 MiB，PDFBox 3.0.8 严格解析，拒绝损坏、加密或没有页面的文件。保留原始 PDF，不修改税务签名。
- 待开票申请在文件写入的同一事务中登记发票号。旧的已登记申请可以按原号码补传。相同号码、相同 SHA-256 重试返回原结果，文件不能覆盖；已驳回申请无法上传。
- PDF 存入独立私有表，通过当前用户与区域鉴权下载，管理端分别要求 `finance:invoice:write` / `finance:invoice:read`。响应使用附件下载、禁止缓存、禁止 MIME 嗅探，不生成公开链接。
- 下载和收件分开：读取文件不会自动确认收到。用户确认提交当前文件 SHA-256，重复确认保留首次时间。
- 管理端上传和下载记录审计，记录不包含文件内容、抬头或税号。页面保留失败输入、防重复提交，切换账号或区域忽略旧请求的返回结果。

## 隐私与迁移

新增 `27_invoice_document_delivery_migration.sql`，当前迁移清单为 03–27 共 25 项。MySQL 的 baseline-14 快照和历史迁移校验和未修改，H2 当前完整结构同步增加文件表。

上传、下载、导出、确认与注销按账户锁协调，停用或注销账户无法新增交付。MySQL 等待锁后的文件读取与返回值使用锁定读取，避免并发重试误用旧快照。注销在事务内删除 PDF 与收件记录，保留既有的最小财务记录。新表初始为空，因此不增加历史注销的 cleanup version。

选择发票模块的隐私导出在 JSON 中包含文件元数据，在 ZIP 的 `invoices/invoice-{id}.pdf` 中包含本用户所有区域的 PDF，每次只加载一个文件。未选择发票模块不打包附件。导出失败或事务回滚时清理新生成文件，无法删除时记录任务 ID 便于运维处理。

PDF 会增加数据库、日志与备份体积。上线前须应用 27 号迁移，备份包含新表，逻辑导出使用二进制安全方式（如 `mysqldump --hex-blob`），`max_allowed_packet` 建议至少 16 MiB。接口详情见 [commerce.md](integration/commerce.md)。

## 范围

本轮交付管理员上传的已开具 PDF，不生成法定发票、不接税务供应商、不发邮件，也不验证上传文件中的金额、抬头或税务签名。真实税务供应商、原生设备文件保存、预发部署验收仍需对应环境完成。
