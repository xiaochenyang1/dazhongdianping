## 交付行为

用户领取任务时冻结标题、要求和奖励。任务后来下线或调整金额，已有领取仍按原条款提交与发奖。用户只能选择本人在当前区域已通过内容审核、仍公开的点评或帖子；后台查看完整正文、图片、关联门店、点评评分和提交说明，再通过或驳回。

状态流转为 `未领取 → 已领取 → 待审核 → 已发放积分`，驳回后可重提。重提增加版本，旧审核请求返回 409；通过审核还会校验查看时的内容摘要，作品正文、图片等发生变化时须重新核验。通过审核、更新余额、积分流水和审计日志在一个事务内完成，并发通过或成功后重试只发奖一次。旧 `/complete` 自助奖励接口在功能开启时返回 409，关闭时返回 403。

Web 和 Flutter 提供任务与作品分页、失败重试、说明草稿保留、驳回原因和状态展示。后台提供状态筛选、成果详情和任务配置，操作受 `operations:creator:read/write` 约束。切换账号、区域或页面生命周期变化时，已失效的异步结果不会覆盖当前页面。

隐私导出增加成果引用、说明、版本和审核字段；注销删除未发奖成果，已发奖成果解除账号关联并清除个人说明。发奖与注销使用一致的账号锁顺序，测试覆盖注销已提交后不能继续奖励。

## 数据迁移与兼容性

[迁移 28](../sql/mysql/28_creator_task_review_migration.sql) 新增冻结条款、作品引用、提交版本、审核结果与 `(region,status,id)` 索引。历史已发奖记录优先从积分流水恢复实际金额，保留原完成状态和时间；不会按后来修改的任务金额补发。

新库使用 `01_schema.sql`、`02_seed_data.sql` 建立 14 号基线，再由迁移器应用 15–28；已有库沿当前迁移历史升级。迁移清单、校验和、MySQL 冒烟与迁移契约已同步到 28。后端与三端创作者页面需配套发布；如果回滚到仍有旧自助奖励逻辑的后端，应先关闭延期功能总开关。

迁移集成脚本默认使用 MySQL 8.4 Docker 容器。新增的 `MYSQL_MIGRATION_TEST_SERVER=local` 模式使用全新的临时数据目录和私有 socket，不连接现有 MySQL 实例，并在结束时清理。
