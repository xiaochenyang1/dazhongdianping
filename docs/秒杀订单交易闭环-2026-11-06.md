# 秒杀订单交易闭环交付记录

2026-11-06。秒杀购买现在生成可支付的订单，接入现有支付回调、发券、退款和商户核销。Web、Flutter、商户端及管理端已配套调整；延期功能总开关和 EU 秒杀开关的默认值仍为 `false`。

商家选择套餐、设置秒杀价格与名额，平台审核通过后用户可购买。下单由服务端冻结价格、币种、活动和套餐标题、券有效期，同时预占活动名额与普通套餐库存。每人每场成功购买一次；取消或超时未付款可重新购买，付款后退款仍保留限购记录。

重复下单返回原订单，重复支付请求复用支付流水，成功回调只发一次券。取消、超时和退款通过统一库存服务保证只释放一次库存。已关闭订单收到迟到支付时进入自动退款，不补发券；渠道暂时不可用时保留待补偿记录，使用同一渠道幂等键重试。核销会锁定对应订单、检查支付及退款状态，退款待审或处理中不能核销，已核销不能整单退款。

Web 与 Flutter 从活动页进入已有交易页面，显示活动来源、付款期限、当前订单和失败重试。商户及管理端订单列表显示秒杀来源。桌面导航在入口较多时可自动换行，浏览器检查同时覆盖导航、搜索和账号控件是否被裁切。

MySQL 验证发现并修复了到期秒的判断差异：数据库查询与支付校验现在都按“到达截止时间”处理。并发用例使用已提交数据和独立事务，测试中显式触发补偿，避免定时任务抢先处理测试订单；原核销用例也补齐了关联的已支付订单。

## 数据迁移与运行

部署前应用 [迁移 29](../sql/mysql/29_seckill_order_migration.sql)，新增订单来源、快照、库存释放标记、参与记录关联订单及自动退款类型。历史参与记录保持历史状态，不补订单或券；历史已关闭、已退款订单标记为已释放库存。隐私删除参与记录不会重新开放已付款订单占用的名额。

全新库先导入 `01_schema.sql` 和 `02_seed_data.sql`，再以基线 14 应用 15–29 号迁移；既有库沿已核实的迁移历史升级。后端与各端页面需配套发布。API 字段、状态及开关说明见[秒杀订单契约](integration/commerce.md#秒杀订单)。

```sh
python3 scripts/ci/seckill-order-integration.py --server local
MYSQL_MIGRATION_TEST_SERVER=local bash scripts/ci/test-mysql-migration-integration.sh
```

首条命令使用全新的私有 MySQL 数据目录、临时账号和端口，运行事务测试并启动真实后端及三个 Web 客户端；结束后清理服务及数据库，不连接既有业务库。CI 和 nightly 已加入 `--server docker` 的 MySQL 8.4 流程，并保留日志、截图和失败 trace。
