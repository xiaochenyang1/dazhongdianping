# 拼团订单交易与灰度运营交付记录

2026-11-08。PR [#35](https://github.com/xiaochenyang1/dazhongdianping/pull/35) 将拼团从组队状态扩展为完整的活动交易与运营链路。功能默认保持关闭；巴黎基础预发不会因代码完成而自动开放拼团。

## 交付行为

每位成员开团或参团时创建独立待支付订单，并在同一事务中占用团队名额和普通套餐库存。服务端冻结活动价格、币种、活动与套餐标题、券有效期和付款截止时间，不接受客户端传入价格或数量。团队和套餐两层并发约束保证超额参团不会产生订单或负库存。

成员支付成功后只更新本人付款状态；最后一名成员付款时，团队只允许一次状态跃迁为已成团，并为全部已付款订单逐单发券。并发支付、重复渠道回调、发券补偿和普通券核销/退款规则保持幂等。

进行中团队到期后，未付款订单关闭并释放库存；已付款订单创建 `refundType=groupbuy_expired` 的自动退款，成功后更新订单、券和库存。提交超时、连接中断或响应丢失等不确定结果保留待处理记录，并使用稳定渠道幂等键补偿。渠道明确返回失败时保留原交易状态、进入后台告警，不由定时任务或“单团修复”按钮盲目重提资金；运营修复结果返回实际处理数和失败数。此前被商户驳回但尚未出账的用户退款，会在拼团到期时安全转为系统自动退款。

管理端新增 `/data/groupbuy-operations`：按管理员区域、城市和门店范围展示最近 24 小时团队、支付转化、退款等待/失败、已成团缺券和库存未释放，并允许有写权限的管理员执行单团幂等修复，操作写入审计日志。终态退款失败另有同范围人工核验队列：确认渠道未退款时保存核验编号和备注并保留告警；确认渠道实际已退款时只把本地退款、订单、券、库存和用户通知状态补齐，不调用退款 API。重复确认成功不会重复释放库存或通知，原渠道退款流水不被人工核验编号覆盖。Micrometer 使用低基数的 `dianping.groupbuy.lifecycle` 与 `dianping.groupbuy.failure` 指标；成功事件在事务提交后计数。

Web 与 Flutter 展示拼团人数、付款进度、截止倒计时和邀请链接。进行中的团队进入截止前 60 分钟窗口时，每位有效成员只接收一次 `groupbuy.deadline` 站内通知；成团发券发送 `groupbuy.formed`。

## 灰度与默认关闭

部署总开关 `APP_LAUNCH_DEFERRED_FEATURES_ENABLED` 必须先开启。拼团随后受数据库 `group_buy` 开关控制：活动规则优先于门店，门店优先于城市，最后回退到区域总规则；同级规则按用户 ID 稳定哈希执行 `rolloutPercent`。CN/EU 的区域总规则均默认关闭，`APP_LAUNCH_GROUP_BUY_FEATURE_FLAG_ENFORCED` 默认开启。

巴黎基础预发继续保持部署总开关、EU 拼团开关和数据库 `group_buy` 规则关闭。只在独立功能验收配置中按小比例、指定门店或活动逐步放量；放量前须完成 [EU 预发台账](EU预发执行与验收台账.md) 的 `GB-01`。

## 数据迁移与回滚边界

[迁移 30](../sql/mysql/30_groupbuy_order_migration.sql) 为团队增加已付款人数和到期扫描索引，将成员关联到活动、区域和独立订单，并增加成员交易状态。历史成员保留为历史参与记录，不补订单、不补券，也不参与新的成团付款计数。

[迁移 31](../sql/mysql/31_groupbuy_rollout_migration.sql) 增加截止提醒去重状态，创建活动/门店/城市范围规则表，并写入 CN/EU 默认关闭的 `group_buy` 区域总规则。新库从基线 14 连续应用至 31；既有库必须沿准确迁移历史升级，不可直接导入全量 schema 覆盖。

应用回滚不会逆转 30、31 号迁移。回滚到旧后端前必须同时关闭部署总开关和数据库 `group_buy` 开关，并确认旧版本兼容新增字段；不得删除成员订单、退款或改写成员状态来回退资金、券和库存。
