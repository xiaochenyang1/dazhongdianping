**本次新发现：EU 延期奖励可通过 CN 入口进入共用积分余额。**

在当前候选 JAR 启动的独立 H2 环境中，显式关闭三个 EU 延期能力，并使用模拟验证码注册了一个 `preferredRegion=EU` 的新用户。此环境仅绑定本机地址，不连接目标服务器或真实支付/发信通道。

| 操作 | 实际结果 |
| --- | --- |
| EU 查询首发配置 | `creatorRewards=false, seckill=false, groupBuy=false` |
| 同一服务以 CN 查询配置 | 三项均为 `true` |
| 新用户 EU 资料、点评和帖子查询 | 积分 0，点评 0，帖子 0 |
| EU 请求完成创作者任务 | HTTP 403，符合预期 |
| 同一登录态改用 `X-Region: CN`，领取并完成 CN 任务 9101 | 两次均 HTTP 200，未提交成果即获得 20 积分 |
| 切回 EU 查询用户资料 | `preferredRegion=EU`，积分为 20 |
| 兑换本次专门创建的 20 积分 EU 测试商品 | HTTP 200，状态“已发放”，余额回到 0 |

兑换商品是临时 H2 中的无实际价值测试夹具，不是实际商户商品，也不代表生产环境已发生损失。当前代码的影响是：如果 EU 发布入口仍接受 CN API 请求并保留开放的 CN 任务，仅关闭 EU 功能不足以隔离未验收奖励；代码与现有种子可以直接组成上述路径。

原因可从下列实现定位：

- [LaunchPolicy](../backend/src/main/java/com/tuowei/dazhongdianping/module/launch/LaunchPolicy.java) 第 20–23 行用 `cn || ...` 使 CN 三项能力始终开放。
- [RegionInterceptor](../backend/src/main/java/com/tuowei/dazhongdianping/common/region/RegionInterceptor.java) 从请求头决定区域；[PublicAuthService](../backend/src/main/java/com/tuowei/dazhongdianping/module/auth/service/PublicAuthService.java) 第 160–172 行认证返回的会话没有区域限制。
- [CreatorService.complete](../backend/src/main/java/com/tuowei/dazhongdianping/module/creator/service/CreatorService.java) 第 70–94 行验证领取状态后直接奖励，没有核验点评/帖子成果。
- [CreatorMapper](../backend/src/main/resources/mapper/CreatorMapper.xml) 第 60–67 行更新和读取共用的 `app_user.points`；EU 积分兑换也从这份余额扣减。
- 现有 [首发测试](../backend/src/test/java/com/tuowei/dazhongdianping/module/launch/LaunchPolicyControllerTest.java) 验证了 EU 请求被拒及 CN 配置保留，但未覆盖同账号跨区领取后兑换。

建议列为真实权益开放前的 P0：增加发布环境可服务区域/能力约束，使关闭的奖励写入不能通过客户端选择区域恢复；同时补跨区回归。创作者任务正式开放时，再完成成果关联、审核条件、奖励幂等和撤销规则。
