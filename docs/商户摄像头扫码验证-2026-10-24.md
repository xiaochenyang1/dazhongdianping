# 商户摄像头扫码交付与验证

日期：2026-10-24。实现已对齐包含隐私收尾与团购标题搜索的主干 `82f2396701ee142aaaca33caf734730711dc4697`；本文记录提交前的本地验证，合并后的不可变 SHA 与 CI 由发布候选执行记录补充。

## 交付行为

- 核销页同时提供扫码与输码。识别成功只填入券码并关闭摄像头，由商户点击确认后核销。
- 要求安全上下文与 `coupon:verify` 权限，优先请求后置摄像头，不请求音频。中英文反馈覆盖非 HTTPS、不支持相机、授权拒绝、无设备、设备占用和识别失败，保留输码路径。
- 使用随制品打包、按需加载的 `jsqr@1.4.0`（Apache-2.0）。视频帧经浏览器 canvas 本地解码；不依赖外部二维码识别服务或 `BarcodeDetector`。
- 每 200 ms 扫描一次，最长边限制 720 像素，不重叠解码。券码只接受去除首尾空白后的 1–64 位字母、数字、下划线或短横线，拒绝链接、内部控制字符和超长内容。
- 识别、手动关闭、组件卸载、页面隐藏、`pagehide` 或核销权限撤销均释放 media tracks、视频与最后一帧。相机授权在关闭后才返回时，也立即释放设备。
- 核销请求期间在动作入口阻止重复提交；后端仍负责券状态、有效期、区域、商户和员工门店范围校验。

## 已执行验证

| 验证 | 结果 | 证明的范围 |
| --- | --- | --- |
| 商户端 `npm test` | 23 个文件、67 项通过 | 包含 9 项扫描器测试和 7 项核销页测试 |

| Chromium + H2 真实后端 E2E | 11 项通过 | 巴黎预订、用户二维码、摄像头扫码核销、点评审核、账号隐私和区域权限 |

扫描器测试用现有 Java ZXing 3.5.3 生成的固定二维码矩阵，再使用真实 jsQR 解码；覆盖延迟授权后的资源回收、播放失败、错误反馈和券码格式。核销页测试覆盖扫码后需确认、防重复请求、非法二维码、授权失败输码和离开页面关闭。

新增浏览器场景通过真实 EU H2 接口注册、下单、本地模拟支付发券并获取后端 PNG，在浏览器中用 `canvas.captureStream()` 提供视频流，保留真实 video/canvas/jsQR 解码。断言识别后券码填入、media track 已结束、确认前没有核销请求；确认后真实核销成功，再次核销返回 `400`，过程没有外部请求。本机首次运行因未安装 Chromium 未能启动浏览器，补齐依赖后全部通过。
