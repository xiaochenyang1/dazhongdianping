## 首发行为

- EU 种子和 25 号迁移只启用巴黎，订单继续只使用 EUR；CN 保留兼容性。预订创建的时段与手填时间两条路径、改期、商户确认以及时段创建/启用，统一校验区域、门店、城市、分类和商圈状态。
- 已停用城市的历史预订仍可查看，允许截止前取消；已确认记录继续提醒，商户仍可拒绝、登记到店或爽约，不能新增或改期进入停用门店。
- 创作者奖励、秒杀、拼团默认关闭。公开 `GET /api/c/v1/launch-config` 按 `X-Region` 返回 `creatorRewards`、`seckill`、`groupBuy`，响应禁止缓存；后端在奖励、库存或组队写入前返回 `403`。Web/Flutter 隐藏入口，Web 禁止延期功能深链接；配置加载失败或切区响应不匹配时保持关闭。普通团购、优惠券及预订继续可用。
- 管理端城市创建/更新必须提交明确的 IANA `timeZone`；缺失、空值、未知时区或固定 offset 返回 `400`。巴黎使用 `Europe/Paris`。

## 预订时间契约

| 字段/操作 | 语义 |
| --- | --- |
| `reserveTime` | 门店当地墙上时间，不带 offset；客户端不得转成设备时区再展示 |
| `timeZone` | 创建/改期时保存的 IANA 时区快照，避免后续城市编辑改变已有预订的时间含义 |
| `reserveAt` | 根据快照换算的 UTC 时刻；取消截止、改期和提醒使用真实时刻比较 |
| 时段接口 `today`、`date` | 门店当地今天和所选日期；省略 `date` 时默认门店当地明天 |
| `canCancel`、`canReschedule` | 服务端根据当前状态、真实时刻和门店可用性计算，客户端直接使用 |
| 新建/改期、时段启用 | 拒绝过去时间、春季夏令时跳过的时间及秋季重复的时间，提示用户另选时段 |
| 历史夏令时重复记录 | 因旧数据没有 offset，统一采用 Java 的较早 offset 规则；新数据不会产生该歧义 |

提醒使用同一个 UTC 当前时刻，按预订保存的时区查询并按实际经过时长验证 2 小时/30 分钟边界；不依赖服务器默认时区，也不只遍历启用城市。Web、Flutter 和商户端展示门店当地日期/时间及时区，日期选择使用门店日历。
