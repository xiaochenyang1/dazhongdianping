**咨询会话列表分页与未读筛选（2026-11-06）**

PR #26 已合并，主干提交为 `29b8eb68989514b3a2a671fbeffcec0f1dff7696`；该提交的 [CI](https://github.com/xiaochenyang1/dazhongdianping/actions/runs/42148472863) 和 [nightly](https://github.com/xiaochenyang1/dazhongdianping/actions/runs/42148654872) 均通过。本轮在此基础上补齐会话列表能力。

用户 Web、商户工作台和 Flutter 支持每页 20 条、上一页/下一页及“只看未读”。后端按活动时间与 ID 做边界分页，最大 100 条，只读取页大小加一条，不执行总数查询。列表接口的 `data` 从数组改为分页对象，三个客户端必须与后端配套发布。详细字段与实时排序边界见 [咨询接口契约](integration/consult.md)。

翻页失败保留当前页，可用原游标重试；筛选从第一页开始，旧请求不能覆盖新的筛选。刷新回到最新页，商户后台轮询只刷新当前页。选中会话与列表分开保存：切换分页、筛选为未读、或读取消息使会话不再符合未读条件时，仍保留正在回复的消息与草稿，线程加载失败时暂停发送并允许重试。

读取消息会清零相应未读数，但显式保留活动时间，避免 MySQL `ON UPDATE` 在标记已读时改变排序。使用现有索引，没有新增迁移，终点仍为 **27**。未读及门店范围过滤可能扫描多条索引候选记录，容量结论限于本次数据分布。
