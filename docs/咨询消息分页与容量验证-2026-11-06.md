**咨询消息分页与容量验证（2026-11-06）**

本轮先将工单、咨询互动与发票交付的 PR #25 合入 main，合并提交为 `ac642e8a4d818d633b31d2b7a00d9a9d461aac3f`，该提交的 [主干 CI](https://github.com/xiaochenyang1/dazhongdianping/actions/runs/42142822796) 两项作业通过。咨询分页在此基础上开发。

用户 Web、商户工作台和 Flutter 现在首次只读取最近 50 条消息，通过“查看更早消息”向前翻页，轮询只拉取新消息。断线后按页补收，历史页和增量页独立保存游标；失败保留消息与草稿，切换会话忽略旧响应。发送成功不会错误地跳过尚未收到的对方消息。

用户 Web 与商户工作台补齐消息气泡、发送者分行、长文本换行及窄屏布局。翻历史保留阅读位置，主动发送后滚到最新消息；商户端复用现有图标样式，修正首次访问的 `favicon.ico` 404。

后端每次最多读取 101 条来形成最多 100 条的响应，使用现有 `(session_id,id)` 索引，无新增数据库迁移。读写同一会话的短事务协调消息 ID 和提交顺序，避免并发发送时漏收；翻历史不清掉新消息的未读状态。详情见 [咨询接口契约](integration/consult.md)。

同时修正商户咨询的门店范围：限定门店的员工，其会话列表、读取和回复均不能访问范围外门店；此前只检查商户归属和功能权限。
